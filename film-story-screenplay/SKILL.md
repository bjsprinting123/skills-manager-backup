# Story & Screenplay

按需读取[故事、场景与对白方法](references/story-dialogue.md)；来源见[Sources](references/sources.md)。

## 核心顺序

```text
谁要什么
→ 为什么现在
→ 什么阻止
→ 人物采取什么策略
→ 结果改变什么
→ 下一场为什么必须发生
```

## 输入模式

- 只有 idea：建立最小 Story Bible，再写需要范围。
- 有 Source Canon：不得越过 preserve / unknown。
- 有 treatment：直接写 screenplay。
- 有完整 screenplay：只按用户点名做修订，不为流程完整重写。

## Story Bible

按需要包含：

- premise / logline；
- audience promise；
- protagonist desire / need / strategy；
- opposition；
- relationship pressures；
- thematic pressure；
- ending promise；
- serial engine（若是连续剧）。

不强迫每个项目使用三幕、固定钩子数或固定人物弧。

## Scene / Treatment

每场至少回答：

- entering state；
- character objective；
- obstacle / pressure；
- visible action；
- information change；
- exit state。

场景不是“情绪标签”，必须发生可观察的状态改变或有意的余韵/停滞。

## Screenplay

写：

- 场景标题；
- 可拍动作；
- 对白；
- VO / OS / SFX / 画面文字（真实需要时）；
- 必要连续性交接。

对白应在争取、躲避、试探、攻击、保护、重新定义关系。不要用对白解释已经演清的动作。

## Dialogue

需要真实互动时考虑：

- 谁拥有话权；
- 谁准备接话；
- 是否打断/重叠；
- 何处失语、改口、沉默；
- 哪个词触发表演变化；
- listener reaction。

这些是表演/写作决定，不在 Provider Prompt 临时发明。

## 禁止

- 不写 Shot List。
- 不指定镜头焦段/运镜来弥补剧本问题。
- 不替 Visual Development 选 Palette。
- 不因为短视频就强制所有场景三秒一个反转。
- 不把抽样研究结论写成 Source Canon。
