# ComfyUI 模型库梳理

从用户提供的目录或文件出发，把权重变成能看懂、能查证、能正确选用的模型说明。用中文解释“它帮我做什么、什么时候选、需要搭配谁”。

默认使用随技能提供的离线扫描器与 Python 标准库，不要求 ComfyUI 运行，也不要求 MCP。扫描与建卡可离线完成；没有已保存的可靠资料时，来源核实仍需联网，不能把“离线盘点”说成“离线确认所有用途”。结合已安装的模型来源、兼容性或库存技能时，阅读 [离线整合与资料分工](references/offline-integration.md)，按需取用线索，不叠加它们的全部指令。

当任务涉及模型改名、移动、去重，或 `comfyui-workflow-docs` 发现的缺失模型、共享模型卡查询、正式入库时，必须阅读 [共享模型资料库与工作流交接](references/shared-library-handoff.md)。只读盘点不自动发布；已授权文件整理时，将已关联本地资料库的当前路径与库存状态同步纳入同一操作计划。

已有模型卡收到新视频、作者参数或用户反馈时，也按上述交接规则评估增量更新；不能只处理索引 missing。先核对当前任务和项目已有的发布授权、精确模型身份与旧revision；授权明确则继续发布，缺授权则明确列出待发布内容并请求确认。

用户要求复核模型卡、组合推荐、保留/替换建议或修正关联文档时，必须阅读 [复核、推荐与文档同步](references/review-and-recommendations.md)。先核对模型卡的原始证据，再与汇总比较；交付包含逐项决定和逐文件状态，不以“建议再测”代替已授权的资料纠正或取舍分析。

本技能是[统一库存状态](references/inventory-state.md)的维护方。涉及模型增删、移动、改名、补卡，或发现库存过期时读取该规范；批量变更完成后刷新一次库存。资料查询命中不代表本地安装；清理表、工作流交接和中文模型卡节点读取同一库存标记，不各自推断。

涉及中文功能名、触发词、LoRA强度、作者示例或中文模型卡纠错时，必须额外阅读[中文模型卡语义与图片证据](references/chinese-card-semantic-audit.md)。涉及NSFW样图分级目视、样图元数据深读、阶梯对照图读数、退役同型排查或中文卡命名精度时，必须额外阅读[模型卡审计配方集](references/audit-recipes.md)；其中命名精度条款（具体部位不得泛化为上位词）与NSFW分级分工（≤4级AI目视、≥8级用户自查）为2026-09-10全库审计沉淀的强制口径。该规范适用于所有LoRA，不仅滑块。先备份将修改的现有文件，再核实统一来源；正式发布仍遵守共享库的单一发布入口，不手改不可变revision或派生模型卡。用户要求全库核对时，以当前索引逐项登记，不能用三个示范模型代替全库完成。

## 执行流程

1. **确定范围并盘点。** 沿用用户指定目录与本轮授权；没有必要逐文件确认。记录扫描时间、文件数、跳过项。先读文件头，按需计算哈希。脚本只读取模型，不加载权重或执行反序列化代码：

   ```powershell
   python "<skill-dir>/scripts/inventory_models.py" "<模型目录>" --out "<输出目录>/inventory.json"
   # 全文件 SHA256 用于身份比对；大库可先只对相同大小的候选组计算
   python "<skill-dir>/scripts/inventory_models.py" "<模型目录>" --hash duplicates --out "<输出目录>/inventory_hashed.json"
   ```

   `--hash all` 用于指定小目录或完整哈希核验。默认不读取全部大文件。脚本给出的目录提示、张量结构提示不等于已核实的用途。

2. **建立待查清单并核实身份。** 用 `scripts/catalog_tools.py prepare <inventory.json> --out <新的研究目录>` 生成逐文件 `catalog.json`、`research_tasks.json` 和中文说明草稿。保留异常文件；初始卡片全部待核实，不能直接作为完成的研究结果。阅读 [研究与解释规范](references/research.md)，逐项查证后填写目录中的卡片。优先用完整 SHA256 对作者发布的精确文件与版本，随后读取该版本的模型卡、作者说明、配套节点或示例工作流；按用户需求另列可定位原文的社区使用反馈。查不到时明确未知及原因，不把旧文件名或评论翻译成事实。

3. **形成可用说明。** 按 [输出与改名规范](references/output-and-changes.md) 为每个权重建立中文卡片，解释角色、适用任务、搭配关系、名称片段、使用方法和局限。相同权重的多个路径可以共用一张卡，但清单不能漏路径。优先帮助用户在已有模型之间选择，再提出有证据的优化建议。

4. **按授权处理文件。** 仅调查或创建技能时只输出建议；用户已要求改名/删除的指定范围，可以生成并核查清单后直接执行，不重复询问。按“内容重复”删除必须有稳定文件的完整哈希相同证据；按用途精简是另一类决定，需说明保留谁、舍弃谁及代价。不同版本不能冒称重复，但可在用户接受已说明的取舍并授权后处理。执行细节见输出规范。

5. **核对交付。** 用 `scripts/catalog_tools.py validate <inventory.json> <catalog.json>` 校验快照绑定、逐路径覆盖与身份凭据字段，再用 `render <inventory.json> <catalog.json> --out <新的说明.md>` 生成中文卡片。校验器不访问来源网页，不能证明填写的证据真实；仍须人工核对存档原文及每项结论。分开统计已核实、部分核实、待核实、文件异常，说明是否做过加载/生成测试。改名或去重后核对磁盘文件、当前工作流引用、资料库当前绑定与索引 revision；逐项记录同步结果和例外。有派生文档时按复核规范检查当前正文、生成源和重新生成结果。输出目录中的报告不等于指定资料库已更新。

6. **关闭交接。** 对本次模型逐项交代“无需更新／待研究／待批准／已发布”，给出原因、后续动作和已发布回执。文件已整理而当前引用或资料库绑定尚未同步时，明确列出缺项，不报告全部完成。工作流转来的任务，在当前任务内回传并核对索引revision、更新工作流引用。只读盘点只报告其授权范围，不自动发布或递归重跑工作流。

## 特别容易混淆的地方

- 文件夹名、扩展名、量化标记、模型角色是四件事；放在 `checkpoints` 的文件也可能是姿态估计器。
- 加速 LoRA、已蒸馏的主模型、量化权重、推理后端加速分别说明；不要承诺低精度必然更快或显存固定下降多少。
- 区分训练 checkpoint 步数与推理步数、LoRA rank 与加载强度、FL2VA 与 Ref2VA、高/低噪声分支。缺少版本依据就不推荐互换。
- diffusers 的 guidance_scale 与 ComfyUI 的 CFG 是不同后端语义，数值不能互填；核对推理配方以下载的官方 workflow_templates 为准。
- 样图工作流字符串被平台截断时只能写"不可判"，不能写"确认无强度/无参数"。
- 发布 request-id 不可复用；同一张卡在一个流程内被多次发布时，每次发布前实时重读当前 revision。
- 作者在 Civitai / Hugging Face / ModelScope 的发布页可以是一手来源；转存仓库只证明它发布了该文件，不能自动代替原作者对效果的说明。
- 未做推理测试时，作者推荐参数、社区经验与本机实测必须分开。不要把平台自动生成的通用代码或模板提示词当作作者用法。

## 与工作流技能配合

目录梳理和模型资料的正式写入由本技能负责。用户同时提供工作流 JSON，或需要验证节点能否加载、连线和参数搭配时，可使用已安装的 `comfyui-workflow-docs` 深入核实。没有该技能也能完成模型卡；不为目录任务虚构工作流输入，不声称文件头检查已经验证实际生成。

两个 Skill 都可以检索网页，但按资料归属写入：模型身份、作者建议和模型社区反馈进入共享模型资料库；节点实现、连线和某一工作流的具体配方留在工作流文档。工作流侧先按完整 SHA256、再按精确版本/远端文件/别名查询；缺失时输出补录请求。本技能在同一任务中接收线索、完成查证并形成 contribution，只有本轮用户已授权正式入库时才调用 `shared_model_library.py publish`。它是模型资料的单一写入入口，不允许两边分别覆盖模型卡，也不假装两个 Skill 会在后台互相调用。

远端资料卡可以在没有本地权重时建立，必须把网页身份状态和本地库存绑定状态分开。工作流里的保存值、作者建议、社区反馈、本机实测和用户选择分层展示；任何一层都不能自动覆盖用户选择或升级为通用默认参数。
