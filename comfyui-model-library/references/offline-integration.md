# 离线整合与资料分工

## 最小运行条件

使用现有 Python 3.12 或更新版本及本技能自带脚本即可，无第三方 Python 包。Python 3.12 的目录 junction 识别用于 Windows 扫描边界。不要为盘点安装 Torch、CUDA、ROCm、ComfyUI 节点、模型权重或 MCP 服务；不要调用上游一键安装器。

`inventory_models.py` 接受一个明确的目录或单文件，递归盘点常见权重格式，安全读取 safetensors 头和 GGUF 最小头，按需计算完整 SHA256。它不读取 GGUF 的完整量化元数据、不自动解析 `extra_model_paths.yaml`、不跨目录 junction 扫描。遇到多模型根目录时，列明用户指定的各个真实根目录，分别生成盘点与卡片；不能把单目录结果说成全机模型库结果。配置中发现的新目录只作为范围线索，不自动扩大扫描。

扫描只读权重，输出仅写入明确的报告目录；不调用 `torch.load`，不执行权重、节点或生成任务。

## 可选技能分工

本技能负责最终证据判断和报告。以下技能可从当前可用技能目录定位，缺失时跳过，不为完成本任务自动安装。没有必要同时加载所有条目。

| 可选资料 | 何时取用 | 不能替代什么 |
| --- | --- | --- |
| `model-registry` | 按模型家族、原始文件 ID 找发布仓库或候选文件 | 清单 URL 不证明本地文件身份；不要因为写了 `download_model` 就要求安装 MCP 或下载权重 |
| `model-compatibility` | 为底模、编码器、VAE、LoRA、加载节点建立待核验搭配 | 通用推荐不等于该文件版本兼容；显存、步数、量化速度不是本机测试结果 |
| `comfyui-inventory` | 用户需要运行中 ComfyUI 的可见模型、节点 schema 或硬件快照时 | 文件目录盘点不证明加载成功，API 下拉列表也不证明文件哈希或来源；离线任务继续用本技能扫描器 |
| `comfyui-workflow-docs` | 用户提供工作流 JSON，或要求核对具体连线、节点参数与引用影响时；它可以查询共享模型索引并输出待补录请求 | 不为单纯模型目录任务虚构工作流；不让工作流侧直接覆盖共享模型卡 |

这些外部 Skill 是可选参考，不是需要修改或复制到本技能中的模型数据库。保留它们的上游安装来源；整合逻辑在本技能维护，避免下次上游更新覆盖本地改造。

资料冲突时，回到精确版本的发布记录、模型卡和加载实现。两个通用表相互矛盾时记录冲突，不能按表格顺序、绝对措辞或安装量裁决。涉及硬件加速时先明确 GPU/后端，不能把 NVIDIA 的架构门槛直接当成 AMD/ROCm 的可用性结论。

## 从盘点到模型卡

```powershell
python "<skill-dir>/scripts/inventory_models.py" "<用户指定模型目录>" --hash duplicates --out "<报告目录>/inventory.json"
python "<skill-dir>/scripts/catalog_tools.py" prepare "<报告目录>/inventory.json" --out "<不存在的新研究目录>"
# 逐项查阅资料并填写新研究目录中的 catalog.json，保持输入快照不变。
python "<skill-dir>/scripts/catalog_tools.py" validate "<报告目录>/inventory.json" "<新研究目录>/catalog.json"
python "<skill-dir>/scripts/catalog_tools.py" render "<报告目录>/inventory.json" "<新研究目录>/catalog.json" --out "<报告目录>/模型库说明-查证后.md"
```

- `prepare` 只建立工作底稿，不联网识别模型。默认每文件一张卡，异常文件也保留。`research_tasks.json` 给出逐文件查证入口，不包含权重任意元数据或私人提示词。
- `--hash duplicates` 只哈希同大小候选；需要身份比对但尚未哈希的文件，要在用户范围内进一步用单文件或小目录 `--hash all` 获取哈希。哈希策略改变会产生新快照，应为新快照重新准备卡片，逐项复核后迁移已查证内容，不能只更换快照指纹以绕过校验。
- 查证用当前可用的网页搜索与页面读取工具。先找原发布者和精确版本，再使用已有注册表和社区资料补充。未联网或来源不可访问时记录原因，继续完成可核实项目。
- 对来源保存 URL、发布方、版本/修订、检索时间、所支持结论；身份确认另保存发布方的完整文件 SHA256，并保留对应网页/API 证据。不要上传模型二进制、私人目录清单或凭据；公开查询只使用必要的文件名、模型 ID、哈希。
- `catalog.json` 绑定输入 `inventory.json` 的原始字节 SHA256。移动输入文件不改变绑定，修改内容则必须重新核验。
- 共享一张卡的多个文件必须是扫描时稳定且完整哈希相同的副本。仅同名、同大小、同家族或同量化格式不够。
- `validate` 检查结构一致性和证据字段，不替你访问证据，也不证明生成效果或速度。草稿全覆盖、资料已查证、实际加载成功是三个不同状态。
- 输出工具拒绝覆盖既有报告；改名/删除仍按 [输出与文件整理](output-and-changes.md) 的授权和执行规则，卡片中的建议名不是操作命令。
- 处理工作流交接、远端单模型资料卡或共享入库时，改用 [共享模型资料库与工作流交接](shared-library-handoff.md) 的 `shared_model_library.py`。该脚本不联网；网页查证由当前代理完成并以来源记录输入。正式 `publish` 必须再次满足本轮授权条件。

## 可核查的交付

报告至少区分：输入文件数、卡片覆盖数、身份已核实/部分核实/待核实数、异常文件数、跳过路径和未测试项。每张未知卡说明缺口及下一步，不用通用搭配文字填满未知字段。完成一轮模型卡不自动更新其他技能、公共知识库或原有正式工作流文档；只有受控发布入口会更新共享模型库，并把发布结果交回工作流侧引用。
