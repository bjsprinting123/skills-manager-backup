# 复核、推荐与文档同步

用于复核已有模型卡、编写组合或精简建议、以及修正模型卡关联文档。沿用用户授权范围和既定选择；一次局部询问不扩成强制全库下载、推理或全网普查。

## 先查模型卡，再查汇总

用户要求复核，或出现卡片与汇总冲突时，先列出检查范围：当前卡片、本地文件、远端候选、隔离文件和当前文档。把历史证据与当前入口分开；卡片数、权重文件数、重新哈希数、来源匹配数是不同口径。

按两个不同角度核对；用户要求“两次自查”时，每轮均覆盖声明的卡片范围，记录各自问题，不把同一个结构校验命令跑两遍当成两次内容审查。

1. **身份轮**：核对发布者、标题、原文件名、版本、完整SHA、本地路径和模型角色。记录重算、沿用且检查文件状态、尚未匹配来源的范围。当前仓库找不到旧文件时可查已知固定revision；本地SHA一致不等于原始发布来源已确认。按任务需要重算哈希，不无条件对未变文件重复读取全库。
2. **内容轮**：对照发布原文检查用途、底模、任务输入、版本后缀、触发词、强度和采样条件。重点检查否定条件、跨版本/框架套用、无依据排名或“取代旧版”、已在库却仍称缺失、参数已撤回却残留在摘要等情况。结构验证、字段齐全或文件存在不算内容事实证明。

先修已确认错误的正式卡片，再与汇总逐项比对；卡片仍待核的字段保持待核。汇总的每个主张能追到精确卡片字段及来源，不能用自建汇总和自建卡互相背书。出现新冲突时针对受影响字段重新查证，不机械重复整轮工作。

完成记录列出已纠正、核对后无需修改、仍缺具体证据的项目。不要把用户要的对比结果改成“先去生图”；资料纠正和取舍分析应在本轮完成，效果验证另报边界。

## 组合推荐

- 按模型家族、任务、组件角色和所需输入组织组合。图片与视频模型、底模与LoRA、普通文生图与参考/编辑/控制链不能因名称接近就混为可互换项。
- 每套说明目标画面、精确文件、每件作用、同时启用情况、强度来源、所需输入/节点类型、缺件及出现问题先调哪件。已有工作流保存值称为快照配置；只有来源确实支持时才称作者建议。
- 用户需要更多选择时可给简单组合及增加LoRA的方案，每增加一件有具体目的，不把两件当上限，也不为凑数量添加组件。各档独立使用；同时改变数量和多个强度是整套设置对比，不是单变量验证。
- 推荐与本地库存分开。缺件但有价值的方案可列候选，给可定位的精确版本/文件、来源及缺失条件；无法定位的名称只作研究线索。按用户目标覆盖库存，未使用项说明原因，不按分类静默遗漏。
- 提示词中的已知触发词、作者声明可选与未说明的词分别处理。作者点名的两件搭配不能泛化成“任意两件同作者模型”。
- 作者搭配建议、完整公开出图配置、社区相近案例、本次提出的试验分别标记。普通用户评论未写文件版本时，不强行绑定成本地同名文件；缺完整设置的条目显著注明不能直接照抄执行。

## 保留与替换建议

先说明用户的取舍目标，例如保留多种画风、减少同类通用底模或节省磁盘。对用户要求比较的文件给出当前决定，不以“同系列、待测试、按需入口”代替结论。

本地保留/清理主表先按[统一库存状态](inventory-state.md)筛选现存文件；资料库有卡不等于有本地权重。缺少的旧版和网络候选单列参考，不能混入本地替换行；只有一个本地文件时单列保留建议，不伪装成两份本地文件的比较。

|决定类型|需要说明什么|
|---|---|
|内容完全重复|哪些路径同完整SHA、保留哪份、引用和实际可释放空间；标题别名不是第二份文件|
|用途精简，可接受损失|保留A、B可舍弃的理由、会少什么能力或后备、把握及其依据、执行前的引用处理|
|继续保留|具体保留理由：用户已指定、独立画风/角色/任务、必要依赖等；不只写“证据不足”|
|仅有资料记录|没有现存文件路径登记，不把它算进删除目标或释放空间；是否有必要补下载另说|
|暂不能决定|缺少哪项会改变决定的证据、下一步具体查什么；不能伪造用途或效果优势|

区别“确认是后续发布版本”和“针对用户用途建议替换”。用途精简不要求A在所有画面上无损胜过B，但必须公开代价和不确定性。用户已要求保留的版本继续保留；建议清单不自动授权执行删除。实际文件操作仍按[输出与文件整理](output-and-changes.md#去重和执行)及共享库交接规范执行。

只读全文搜索命中的保存JSON可能是注释或关闭节点。报告扫描范围和命中性质；真正修改/删除前按节点语义核对，不能把“零文本命中”说成全机无依赖。

## 当前文档与生成源一起收尾

1. 列出本次受影响的当前文档、模型卡派生入口、结构化推荐和读取这些数据的界面。先记录当前版本；用户说“所有文档”时说明实际覆盖目录，不能只抽查一篇就声称整体通过。
2. 从明确的数据源导出数量、库存、哈希范围和状态；同一字段在所有当前入口一致。修卡后更新摘要、限制、比较表及下载说明中的旧说法。名称解释分栏写发布页标题、原下载文件名、本地文件名及对应证据，核对工作由代理完成。
3. 修正文案同时修生成来源。容易互相覆盖的多步生成使用完整刷新入口或等效保护，避免单独运行中间步骤把旧事实写回。旧报告保留日期及历史性质，当前入口指向最新结果；不可变revision和原始来源按交接规则保留。
4. 验收同时检查数据一致性和语义：路径/链接、卡片版本、组件数量与启用、任务输入、参数来源、错误分组和陈旧文字。参数未知不能被“文件齐全”掩盖。按具体目的阅读当前正文，字符串未命中不等于所有内容正确。
5. 有生成链时重跑完整链，比较应稳定的文档和数据，排除合法时间戳等变化；确认旧结论未被写回。发布数据、界面显示和实际生成分别报告，未打开界面或未出图就保持未验证。

交付给用户的主表先放“做什么、现在怎么选、为什么、下一步”，完整路径和SHA可放核对附表。逐文件列出已改、无需改、未完成及理由；被本轮发现但尚未解决的问题在最终回复点明。避免继续增加多个互相矛盾的“最终报告”。
