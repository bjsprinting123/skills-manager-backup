# 中文模型卡：准确功能、提示词与强度语义

适用范围：所有LoRA及其中文模型卡、浏览器显示、组合推荐引用。此规范是现有模型库维护流程的补充，不建立第二套模型知识库，不改变正式发布授权、身份校验或不可变revision规则。

## 先保护原文件，再逐项核对

修改前备份实际将修改的现有文件，记录原路径、备份路径和核验结果；新增研究记录不冒充已备份全库。保留历史revision、历史推荐和用户选择，不改权重文件名，不下载权重，不运行生成，不顺带处理短剧Skills吸收项目。

以当前model-index.json的model_id和current_revision确定范围。分别统计模型卡数、LoRA数、本地权重路径数、远端候选数。每项记录正文、精确版本、触发词、图内标注、图片元数据、嵌入工作流、实际像素观察及发布状态。未读到的来源或图片不得勾选完成。

## 逐卡对照，不通扫后批量套模板

用户于2026-09-09补充要求：一张一张、逐项对照，修改后必须自查，全部完成后还要独立复查；该要求是交付门槛，不是可选建议。

批量工具只能帮助建立清单、定位原始来源或提取待读字段，不能代替逐卡阅读，也不能把“网页有参数字段”标成内容已核实。不得先粗略扫全库，再按关键词或统一模板改写所有卡片。

对每张卡按以下顺序处理并留存记录：

1. **读原卡。** 读取当前索引指向的完整contribution及可读卡，列出原中文功能名、必需提示词、作者值、范围解释、例图、适用条件与限制。不能只看summary。
2. **逐项对照来源。** 以精确发布版本核对作者正文、版本说明、图内文字、画面变化、Generation data和有效节点连线。每项填写“原卡怎样写—来源实际怎样说或显示—差异—处理决定”，而不是只记录来源链接或字段是否存在。
3. **该卡查明后再改。** 先保存原件备份，再通过现有模型卡Skill准备增量contribution并按正式发布规范更新。保留正确旧事实；缺失证据精确登记到字段、图片或档位，不自动补猜，不把读取失败改写成作者未提供。
4. **修后立即回读。** 重读实际保存的候选；正式发布后另读索引指向的新revision、派生模型卡和可访问的显示入口。对照本卡差异表确认修改落地、旧错误不残留，并保留未发布或显示不可验证的明确状态。
5. **再登记下一张。** 已核对无需修改也必须有对照记录；遇到来源或发布阻碍，明确登记本卡未闭合原因后继续其他卡，不把阻碍项算成已完成。

每条差异记录至少包含：model_id、核对时的current_revision、字段、原表述、来源定位（原文段落或图片ID及区域）、证据类型、对比结论、拟修改内容、保存/发布状态、修后回读结果。记录是审计轨迹，不是供组合推荐读取的第二套模型事实库。

## 功能名不能扩大能力

中文功能名说明实际用途；本地完整文件名、原发布文件名、版本和SHA单独保留。不能仅因旧文件名写了泛称，就沿用它作为准确功能。

例如Monolid须明确为单眼皮功能或单眼皮倾向滑块，不能写成万能眼型、双/单眼皮切换器或任意眼睑编辑器。负值是否可形成某种相反效果，需对应作者说明或对照图；不能按名称或正负号推断。显示名纠错不自动授权重命名磁盘文件。

## 命名落到具体部位，不得泛化为上位词

中文卡名称与「定位」句必须写到模型实际作用的**具体部位+方向**：足部概念就写「足部特写」，不得写「成人局部概念」；臀胯突出+腰细就写「臀髋强化细腰」，不得只写「体型比例」；单眼皮眼睑就写「单眼皮」，不得写「眼部」。上位词让用户在选卡时完全猜不到实际作用，与"功能名不能扩大能力"同源：既不扩大，也不泛化。命名自查法：把名字给没读过卡的人看，猜不出或猜偏即命名失败。细节与案例见[模型卡审计配方集](audit-recipes.md)第一节。

## 必需提示词不能漏读

分别核对模型正文、所选版本正文、trainedWords、作者示例提示词及图片内说明。记录原样词、必需/建议/作者明确无需/条件必需/尚未确认、使用位置、适用任务和来源。

trainedWords为null或空列表，只能说明该字段未列出词，不能写成无需触发词。示例里出现一个词，不自动证明它是强制触发词；作者在图内写明必须添加时，必须提升为有来源的明确要求。用户指出作者有要求时，定向复核原文和图片，不以空字段否定用户。

## 所有LoRA都必须解释作者值与范围

| 已查到的证据 | 中文模型卡应呈现 |
|---|---|
| 作者只推荐1.0 | 明确写“作者推荐：1.0”，附版本、宿主和条件。不得改成待校准或擅自给新范围。 |
| 作者给范围和起点 | 原样记录范围与起点；解释该LoRA各有据档位改变什么、适合什么目标、可能牺牲什么。 |
| 作者只给范围 | 继续核对样图、图内标签和生成数据；有证据才解释档位，不机械三等分编造低/中/高。 |
| 作者解释超过1.0的效果 | 记录原解释和适用条件；不能仅因为超过1.0就写成过强或不可用。 |
| 只有示例用值 | 标成“作者发布页示例使用值”，不能标成通用作者推荐。 |
| 某档没有证据 | 精确说明缺哪个档位或条件，不用“都没参数”盖掉已经查到的值。 |

每个有据档位使用以下结构：

`数值/区间 → 这件LoRA的具体变化 → 何时选 → 代价或副作用 → 证据类型、原文/图片ID、运行条件`。

不要给不同LoRA复制同一套“低自然、中最好、高失真”。风格强度、人物特征强度、加速适配器强度及控制节点强度含义不同。rank、训练步数不是LoRA加载强度。0、No LoRA和1.0不得混为基准；没有LoRA通常只是对应提示词/宿主的参考图，不是固定的人物年龄或外观。

## 图片和工作流是必查证据，不是装饰

逐图区分：上传图尺寸与实际生成尺寸、拼接子图标签与顶层resource权重、相同seed与严格单变量对照。相同seed但提示词/模型/采样不同，不是严格强度对照。

只读解析meta.comfy，不导入执行。检查节点实际连接：字段存在不等于生效。LoraLoader的CLIP输出未接入正文编码时，不能把strength_clip记录为有效调节结论。上游尺寸节点覆盖了界面残留值时，以有效连线和参数为依据。

按精确文件分组样图。同名但hash未核不能写成同一字节；不同hash、pruned后缀或不同宿主精度不能直接混成作者范围。保留可用样图信息，同时显式列出文件绑定缺口。

## 资料、显示与推荐必须同源

作者推荐、作者示例、社区案例、视觉观察、本次设计选择、本机实测分别标记。不能把所有author_recommendations.parameters展平后统一叫作者推荐。新增示例字段前，应同时检查现行schema、验证器、模型卡渲染器和浏览器读取契约；未实现的字段不作为已发布接口。

更新来源后检查summary、limitations、origin.known_hints.usage_record及中文显示是否仍残留“本轮未查到”。历史revision不改；当前视图不得用旧摘要遮住新证据。

先经shared_model_library.py的正式发布流程维护模型库，再从已提交revision编写组合推荐。工具不允许合规调用发布器时，保留待发布候选并明确报告未发布，不能手工覆盖生成模型卡或关闭保护。修改开发源码不等于运行中的ComfyUI节点已部署。

## 全部处理后的独立自查：必须另做一遍

逐卡修后回读不替代最终自查。全部处理后，从当前正式索引重新列出本次范围，再把每张最终卡与一手来源重新对照；不能只阅读自己刚写的说明，不能重复运行结构校验就称第二轮内容自查。

自查分两条方向进行：从作者原文、图内要求和示例出发，检查卡片是否漏译、漏项或漏条件；从卡片每一条具体结论出发，检查是否有来源支持、是否夸大用途或混淆数值性质。特别复查否定句、必须/可选、正负号、范围端点、0与No LoRA、超过1.0的解释、文件版本及有效节点连接。

最终自查至少逐张确认以下事项，并记录实际发现与修正，不能只勾总完成：

- **范围完整。** 用model_id核对清单与当前索引，核实本地、远端、旧版等实际纳入范围；未看、未改、无法访问、未发布、显示未验证分别列出，不能静默遗漏。
- **语义准确。** 准确功能名未扩张能力；必需提示词及使用位置未漏；作者推荐值、范围、各有据档位效果与副作用解释准确。没有证据的档位未编造；作者有明确1.0时未被待校准覆盖。
- **证据对应。** 作者推荐、示例用值、图片观察与本机实测未混用；图内数值与拼接元数据分开；精确文件、版本、宿主和节点条件未串用。未看像素的图片仍标未看，不因取得URL或元数据而升级。
- **修正落地。** 重读实际正式revision和当前模型卡，检查旧summary、limitations及usage_record未继续显示已纠正的错误；可访问的中文显示与统一资料源一致。源码已改、正式库已发布、运行界面已验证分别统计。

自查发现任何问题，返回受影响卡重新取证、备份和修正，再复查该项及受影响的显示/引用。记录“首次核对结果”和“独立自查结果”两列；未完成第二轮不得报告全库核对完成。

## 完成判据

逐模型分别报告：已核对无需改、已查明待发布、已发布、显示待验证、仍缺具体来源/档位。结构校验只算结构检查；元数据读取只算元数据读取；图片未看像素不得写视觉核对通过。

只有模型卡逐项核对、正式修正和独立自查完成后，才进入优化与组合推荐。存在未发布或尚未验证的相关事实时，不用组合文档替代修卡，也不把候选草稿当正式来源。组合推荐先只产出一份试阅；每个组合按目标重新选择宿主与成员，不固定套用年龄＋单眼皮＋细节，不为凑件数添加LoRA。试阅通过前不批量扩展。
