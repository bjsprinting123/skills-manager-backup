# 通用短剧创作

先读[共同约定](references/runtime-contract.md)。本包包含所需文字知识，不要求其他Skill、原始研究库、生成模型或账号。按当前任务读取下表对应资料，不每次加载全库。

## 进入任务

识别用户要的是讨论、剧本、资产规划、分镜还是修订。可以从中途进入。只有一句想法也先形成有用提案；不要求用户填写完整创作表。用户明确要完整前期包时完成所需阶段，不每一步都停下来索要确认；重大方向冲突才提问。

1. 提取已定事实和核心感受；未定内容标提案。确保世界规则、人物关系和台词不被类型套路改写。
2. 按任务开发梗概／分场／对白；动作和表演提供可见依据，内心动机不自动变成旁白。
3. 从关键镜头反推最少充分资产，写每张用途、继承／排除和可见部位。未取得的图只写需求，不造文件或引用。
4. 分镜明确观看任务、机位、主体位置、事件与反应、时间、声音和结束状态。分清故事长度、镜头长度与生成单元。
5. 交付前检查意图、空间、身体占用、台词与时序、接点和素材状态；有冲突先给解决提案。
6. 若用户要求生成提示词，按实际模型转换；本包未调用其他Skill也能交通用文字设计。找到用户认可的专用包后才读取它，不假定自动调用成功。

## 交付形状

使用[前期交付模板](references/deliverables.md)，只输出当前任务需要的部分。简单讨论不用八张表；完整包不能只给一张空分镜表或“建议找导演”。

文字层的完成条件是：用户所要的阶段有实际内容、关键事实保留、暂定项与素材缺口清楚、接续可理解。实际画面、运动、声音和用户接受属于后续证据，不提前宣布成功。

出处和版本见[依据](references/sources.md)。浏览来源只在核新事实时需要，日常写作不依赖联网。
