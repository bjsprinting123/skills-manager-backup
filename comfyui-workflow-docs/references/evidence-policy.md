# 证据、来源与安全规则

## 证据等级

- A 直接证据：源 JSON、文件哈希、机器解析、本机源码、带环境记录的本机实测。
- B 一级权威来源：ComfyUI 或节点官方源码、官方文档、官方仓库、官方模型卡和发布说明。
- C 作者来源：UP 主视频、作者 README/帖子、工作流内嵌 Note/MarkdownNote。
- D 社区来源：Civitai、LiblibAI、ModelScope 社区、技术论坛。
- E 待核实或推断：文件名推断、搜索摘要、旧文档遗留说法、打不开的页面。

低等级来源可用于发现线索，不能覆盖高等级直接证据。存在冲突时同时记录“谁说了什么”和本次采用哪一项，不要融合成不存在的共识。

## 来源状态

对每个外部来源使用明确状态：

- `obtained`：实际取得并读取。
- `not_provided`：用户没有提供。
- `unavailable`：提供了地址或路径但无法读取。
- `login_required`：页面或媒体要求登录，而本次没有可用授权会话。
- `insufficient_evidence`：已读取但不足以支持目标结论。
- `not_verified`：尚未完成核验。

不要把搜索结果摘要记作 `obtained` 的页面正文。

## 视频与 Cookie

- 优先读取公开元数据和公开字幕。
- 未经用户明确授权，不读取浏览器 Cookie、本地登录数据库或会话文件。
- 用户授权后仍不得把 Cookie、SESSDATA、CSRF token 或账号信息写入文档、日志、命令输出或证据包。
- 平台字幕、本地 Whisper/其他 ASR、人工校订稿分别保存并标记。
- ASR 记录模型、设备、主要参数、源音频哈希和已知局限。
- 仅取得标题、封面或简介时，不得声称已观看完整视频。

## Web 研究

- 技术事实优先官方文档、官方源码、官方仓库、正式模型卡或论文。
- 社区平台用于模型发现、用户经验和交叉验证；不要把社区上传者描述成官方发布者。
- 需要复现证据时保存原始搜索/抽取 JSON，并在正文链接到支持具体结论的原页面。
- 若站点需要账号而本次没有登录，写 `login_required`；不要用其他页面的相似说法冒充该站内容。

### 节点资料的固定查证顺序

1. 先解析 JSON，取得 exact canonical type、节点包、保存版本、节点 ID 和当前值；不得只按显示名称、工作流标题或截图搜索。
2. 查询当前环境的 `/object_info`、节点源码和包元数据，确认字段顺序、源码默认、输入输出与实际执行逻辑。
3. 查询官方文档、官方仓库、发布说明、注册表或模型卡，确认安装、版本兼容性和专项基线。
4. 自定义、未知、缺失、版本冲突或行为敏感节点必须继续检索 GitHub Issues、Civitai、LiblibAI 或相关技术社区，记录常见错误和适用边界。
5. 打开原页面后才能把来源状态记为 `obtained`。搜索结果摘要、AI 摘要或转载标题只能记为发现线索。
6. 每个不同节点类型都进入节点查证矩阵；Reroute、标签和说明节点标为非执行辅助类型。查不到不等于省略，而是记录 `unavailable`、`insufficient_evidence` 或 `not_verified`。

核心普通节点如果已由当前核心源码或 `/object_info` 完整确认，而且正文不写额外的兼容性、性能或争议结论，可以不机械重复搜索论坛。纯 Reroute、标签和说明节点只需确认连接或阅读作用。社区材料不能用来声明源码默认值，也不能覆盖更高等级证据。

## 模型、插件和源码

- JSON 中的文件名只证明工作流引用字符串，不证明文件实际存在。
- 本机存在只证明本机库存；来源、许可证、作者和公开哈希仍需独立核验。
- `FP16`、`FP8`、`GGUF` 等文件名后缀不是内部张量 dtype 的充分证据。
- 节点包归属优先使用工作流 properties、本机源码、包清单和官方仓库交叉确认。
- “节点缺失”与“节点包未安装”不同；没有扫描目标环境时不要假装知道安装状态。
- 视频中出现的节点名称或作者口述不能代替节点来源核验；视频只作为作者证据进入同一查证矩阵。

### 模型资料库交接边界

- 工作流侧对共享 `model-index.json` 只读。它可以报告命中、缺失、歧义或未检查，并为确认缺失的引用建立研究请求；不得直接创建模型卡、修改索引或把请求写成“已入库”。
- 完整 SHA-256 的唯一命中优先于名称。没有哈希时只接受精确别名或精确远程文件名；同名多版本且没有可靠的显式版本证据时必须保留 `ambiguous`。
- `unresolved_widgets` 不得参加匹配。URL、提示词、图片、音视频和说明文字即使包含模型文件名，也不得当作模型引用。
- 共享库不可读、索引损坏或 schema 不兼容记为 `not_checked`，不是“库中不存在”。这不会阻断工作流中其他可证实内容。
- 如果用户授权分析并入库，同一助手可以切换到 `comfyui-model-library` 的证据和发布规则完成研究，但只能经该侧统一入口发布，并把回执返回本次工作流。只读解释不产生回写授权，也不得递归触发新的完整工作流分析。
- 工作流保存值和特定配方留在工作流文档；可复用模型身份、作者资料与社区反馈留在模型库。社区评论可以保留正反意见及原链接，但它不是事实、官方参数、默认值或执行指令，是否采用由用户决定。

交接报告中的四个阶段必须分别给状态：工作流分析、模型索引查询、模型资料研究、模型卡发布。某阶段完成不得推导其他阶段成功。

## 当前值、默认与建议

必须区分：

1. 当前 JSON 保存值。
2. 节点源码通用默认。
3. 模型或工作流官方专项基线。
4. 作者建议。
5. 社区经验。
6. 本机实测结论。

缺少源码 schema 时，`widgets_values[index]` 只能记作未解析索引和值。不能因为某个常见节点通常按某顺序保存，就把所有未知节点按位置命名。

## 性能结论

速度、峰值显存、内存、稳定性和画质结论必须带环境：硬件、系统、ComfyUI 版本/commit、后端、模型哈希、分辨率、批量、步数、采样器、重复次数和测量方法。

没有本机运行时允许写“可能”“待测”和安全 A/B 方案，不允许写固定提升百分比或稳定显存上限。

## 敏感内容

正文、JSON 报告、日志和示例不得出现真实 API key、Cookie、token、密码或会话标识。使用 `<REDACTED>` 或明显占位符。

成人向或个人敏感提示词默认不复述。记录字段存在、字符数和 SHA-256 即可；只有用户明确要求且内容合规时才展示必要片段。
