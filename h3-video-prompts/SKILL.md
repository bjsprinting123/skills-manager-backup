# MiniMax H3视频提示词

先读[共同约定](references/runtime-contract.md)和[共同格式](references/h3-common.md)。本包含规范精炼资料，不依赖其他H3 Skill或在线Hub。普通写稿不需模型权重／账号；实际生成由用户的环境承担。

**包内两层资料，不要混用**：`official-h3-base-en.md`／`official-h3-ref-en.md` 是**官方规范原文**（字段顺序、标签语义、运镜词表、四模式完整示例；格式拿不准或要抄示例时以它为准）；其余 `.md` 是**中文工作层**（工作流程、常见坑、交付纪律、与本地工作流的接口边界）。对应关系与来源 commit 见[官方规范对应索引](references/official-guides-index.md)。

## 工作步骤

1. 区分想法、确定分镜、真实参考与待补材料。简单想法可直接写一个单段提案；不要求完整剧本或工作流JSON。时长未定可在说明中提暂定值，不冒称用户确认或工具上限。
2. 按素材真实职责选模式，读取下面对应指南。模式由目标关系决定，不因照片有人就一律Ref2VA。
3. 实际查看需要引用的图片／视频／音频；能力不足或文件缺失时说明。用户提供的文字说明可作方案依据，但不称亲眼看过。关键素材缺失而影响身份／起终状态时先询问；可交不含假引用的文字方案。

   只写提示词时，工作流JSON或节点截图不是前置条件。缺素材时只索取必要素材和创作目标；接入方式未知可按用户说明的顺序写候选映射并注明待核。只有用户要求接线诊断或需要定位实际引用失败时，再邀请其选提供相关截图／去敏工作流，不把它们与上传参考图捆绑成必交清单。
4. 写清当前取景、主体与世界位置、触发和回应、运动路径、发声与结束状态。配额与风格不从样例自动继承。
5. 按模式组织完整正文。中文审阅说明、输入映射与模型正文分开；用户只要正文时省略不必要说明，不隐藏重要能力缺口。
6. 自审字段／标签闭合、台词原话、切点、总时长、互斥动作、已完成状态及前后接点。读[交付检查](references/templates-and-checks.md)。

## 模式路由

| 任务 | 必读 |
|---|---|
| 纯文字生成，T2VA | [基础模式](references/h3-base.md) |
| 完整画面作为开场，I2VA | 基础模式；确认图是首帧，不只是身份参考 |
| 指定首尾／只指定尾帧，FL2VA／L2VA | 基础模式；确认帧锚入口和相容路径 |
| 借人物／场景／风格／动作／音色生成新片，Ref2VA | [全参考模式](references/h3-reference.md) |
| 视频编辑／续接／音频复用 | 全参考模式；确认源文件、真实接入和支持范围 |

## 按难点读取

| 难点 | 资料 |
|---|---|
| 资产职责与版本 | [资产A](references/methods/A.md)、[项目记录](references/project-records.md) |
| 多人站位、遮挡、一镜到底、机位与转场 | [空间S](references/methods/S.md)、[镜头C](references/methods/C.md) |
| 情绪渐变、听者反应、对白或声音跨切 | [表演P](references/methods/P.md)、[声音时间E](references/methods/E.md) |
| 打斗、追逐、骑乘或手部接触 | [动作M](references/methods/M.md)，涉及空间或声音时再读S/E |
| 多镜交付或版本衔接 | [组织R](references/methods/R.md)、project-records |
| 实际视频／图片不满意 | [修订分流](references/repair.md)；先查资产、引用、动态、声音，不无限扩写 |
| 明确要求改进本Skill | [维护流程](references/maintenance.md)，不要把单镜修订当永久改规则 |

模型模式文档、实际工作流能力和推理成功是三件事。未知参数留在说明，不编造采样器／节点／参考上限，也不把原生节点行为推广到所有第三方工作流。[来源与版本](references/sources.md)供查证，新能力再联网核实。
